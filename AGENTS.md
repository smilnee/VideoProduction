# MicroStation demonstration-video rules

Read [the template overview](README.md). For recording, camera tours, development
footage or Camtasia edits, load the
[production skill](.github/skills/microstation-camtasia-video/SKILL.md).
Documentation-only work must leave applications, models and timelines untouched.
For Copilot adoption/setup, follow
[the setup prompt](.github/prompts/setup-video-production.prompt.md) without
starting production. For publication, follow [access requirements](ACCESS.md):
never equate a private personal repository with enforced Bentley identity,
and upload only reviewed template files, not project media or credentials.

## Scope and tools

- Work directly toward the requested film; ask only for consequential missing
  scope, destination, monitor or presentation decisions.
- Use MicroStation MCP for all model, material, level and view operations.
  Prepare native Python, read API corrections, validate identical source and
  execute with a fresh request ID. No simulated MicroStation input or external
  DGN writing. Discover deferred tools before use.
- Use Camtasia MCP to inspect, edit, open, save and play the editor project.
  Recording may use Camtasia Recorder MCP or verified host-side screen capture;
  identify the recorder actually used.
- A camera-only request authorizes no geometry changes. Verify the actual
  file/model, units, writable/pending state, selection and applicable project
  authority. Never import another project's counts, gates or coordinates.
- Protect the original project and media. Preserve unrelated clips and settings.
  Restore affected MicroStation views, selection and protected clips afterwards;
  keep MicroStation open unless the user asks otherwise.

## Genuine footage and quality

- Record the whole intended monitor by default, including application UI and
  the real agent panel. Exclude unrelated monitors. Cropping/window-only capture
  requires explicit authorization; application footage padded with black is not
  whole-screen recording.
- Show real chronological camera/work activity. Never replay completed geometry,
  hide finished work or manufacture typing/construction to fill a recording gap.
- Test a short representative take before production. Use smooth, readable
  detail/context transitions and one deliberate focus per requested feature.
  Keep a consistent, tested rendering mode; do not mix shading-changing paths.
- Completion requires decoded output, actual moving-footage/detail inspection,
  saved Camtasia playback and model/view/timeline preservation checks.
  Counts, timestamps, stillness scores and dispatch success are not no-flicker proof.
- Report unresolved geometry popping, edge aliasing or depth artifacts explicitly.
  Do not declare a no-flicker requirement passed while visible artifacts remain.
- Default to silence and no added titles/captions. Different creative choices,
  model edits or intentional changes to the existing edit require clear scope.
